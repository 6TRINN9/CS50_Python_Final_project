🔐 Password Manager
Приложение для безопасного хранения и генерации паролей с графическим интерфейсом на PySide6.
Все данные хранятся в локальной базе SQLite. Поддерживаются все CRUD-операции, поиск по заголовкам, встроенный генератор криптостойких паролей с оценкой их энтропии и стойкости.

🔄 Генератор паролей:

Длина от 1 до 30+ символов (слайдер).

Выбор типов символов: a-z, A-Z, 0-9, символы пунктуации.

Криптостойкая случайность (secrets + shuffle).

📊 Оценка стойкости пароля:

Вычисление энтропии (бит) на основе реально использованных классов символов.

Качественная шкала: Pathetic (<50 бит), Strong (50–100), Excellent (>100).

🗄️ Локальное хранение: SQLite с автоматическим созданием таблицы и индекса.

🔍 Поиск по заголовку в реальном времени.

🖱️ Удобный интерфейс: таблица с выделением строк, подтверждение удаления.

🔒 Безопасные запросы: параметризованные SQL-запросы защищают от инъекций.

🚀 Установка и запуск
1. Клонируйте или скачайте проект
bash
git clone https://github.com/your-repo/password-manager.git
cd password-manager
2. Установите зависимости
bash
pip install pyside6
3. Скомпилируйте файлы интерфейса (если отсутствуют src/ui/*.py)
bash
pyside6-uic ui_main.ui -o src/ui/ui_main.py
pyside6-uic ui_new_note.ui -o src/ui/ui_new_note.py
pyside6-uic ui_generator.ui -o src/ui/ui_generator.py
Примечание: исходные .ui файлы не входят в архив с кодом, но их можно восстановить из обратного инжиниринга или пересоздать.
В текущей версии предполагается, что ui_*.py уже сгенерированы.

4. Запустите приложение
bash
python main.py
При первом запуске автоматически создастся файл базы данных manager_db.db в корневой папке.

🗄️ База данных
Таблица m_pass имеет следующую структуру:

Поле	Тип	Описание
ID	INTEGER(PK)	Автоинкрементный первичный ключ
Title	VARCHAR(50)	Заголовок (например, "Gmail")
Login	VARCHAR(50)	Имя пользователя / email
Password	VARCHAR(100)	Пароль (хранится в открытом виде)
Url	VARCHAR(200)	Адрес сайта
Created	VARCHAR(20)	Дата в формате ISO (YYYY-MM-DD)
Безопасность: В текущей версии пароли не шифруются. Для реального использования рекомендуется добавить симметричное шифрование (например, cryptography или keyring).

Индекс: idx_title на поле Title для ускорения поиска.

🖥️ Использование
Главное окно
После запуска открывается таблица со всеми сохранёнными записями, отсортированными по дате создания (сначала новые).
Колонка ID скрыта, но используется для редактирования/удаления.

Панель инструментов:

Создать – открывает диалог добавления записи.

Редактировать – изменяет выделенную строку.

Удалить – удаляет выделенную строку (с запросом подтверждения).

Поиск – поле для фильтрации по заголовку (регистронезависимо).

Создание записи
Нажмите «Создать».

Заполните поля:

Title – обязательное (рекомендуется).

Login – логин или email.

Password – можно ввести вручную или нажать на кнопку генератора 🔄.

Url – веб-адрес.

Нажмите «Create».
Дата Created будет установлена автоматически на текущий день.

🔑 Генератор паролей
При создании или редактировании записи нажмите на кнопку с иконкой шестерёнки (или 🔄). Откроется диалог:

https://docs/generator.png

Длина – регулируется слайдером, отображается числом.

Набор символов – выберите нужные типы (хотя бы один).

Repeat – сгенерировать новый пароль.

Поле пароля – отображается сгенерированный пароль.

Энтропия – например, Entropy: 78.45 bit.

Оценка – Strength: Strong.

Нажмите «OK», чтобы вставить пароль в основную форму.

Совет: Для максимальной стойкости используйте длину не менее 12 символов и все 4 типа символов.

Редактирование и удаление
Редактирование: выделите строку → «Редактировать» → измените данные → «Edit».
Дата Created обновится на текущую.

Удаление: выделите строку → «Удалить» → подтвердите. Запись исчезнет.

Поиск
Начните вводить текст в поле Search – таблица мгновенно фильтруется по полю Title.
Очистите поле, чтобы показать все записи.

🏛️ Архитектура приложения
Синглтон Data – централизованное управление подключением к БД. Все диалоги используют один экземпляр.

Главное окно – владеет QSqlTableModel для отображения данных в QTableView.

Диалоги – работают с БД напрямую через экземпляр Data и по завершении сообщают главному окну об обновлении (update_model()).

Разделение логики – генерация паролей и расчёты вынесены в utils.py.

🔬 Детали реализации
Генерация паролей
Функция generate_password():

Использует secrets.choice для выбора символов каждого требуемого типа (гарантирует хотя бы один символ из каждой категории).

Остальные символы добираются случайным образом из объединённого набора.

Перемешивание выполняется с помощью secrets.SystemRandom().shuffle для устранения порядка вставки.

Исключение похожих символов (il1Lo0O) реализовано в коде, но закомментировано – при необходимости легко включить.

Расчёт энтропии
Формула:
энтропия = L * log2(N), где

L – длина пароля

N – количество возможных символов, определяемое динамически по фактически использованным классам.

Пример: пароль "MyDog123" содержит строчные, прописные и цифры → N = 26 + 26 + 10 = 62.
L = 8 → энтропия ≈ 8 * log2(62) ≈ 47.6 бит.

Оценка стойкости (условная):

Энтропия	Оценка
≤ 50 бит	Pathetic
51 – 100 бит	Strong
> 100 бит	Excellent
Безопасность запросов
Все SQL-запросы формируются через QSqlQuery с использованием prepare() и addBindValue(). Это полностью исключает SQL-инъекции.

Пример:

python
query.prepare("INSERT INTO m_pass (Title, Login) VALUES (?, ?)")
query.addBindValue(title)
query.addBindValue(login)
query.exec()
